## 可复现的问题

1. 同秒收据与完成项顺序错误。先写 needs_review，再在同一秒写 passed，第二份收据文件名带微秒，第一份只精确到秒。`latest_receipt` 按文件名字典序取末项，秒级文件名中的 `Z` 排在微秒数字后，因此误取第一份收据。本次 `d-20260913-readme` 已 done，但归档仍显示旧 summary「README 加了简介，等你看一眼」，没有显示最新「合入」。另一个问题是完成时间只有秒级精度，先后完成 fixture 0、1、2、3 后，notes 保留 2、3、0，较新的 1 先被归档。[原始 notes](../internal/d-20260913-pr-5-a-d-f-cli/notes-after-five-completed.md)和[归档](../internal/d-20260913-pr-5-a-d-f-cli/archive-after-five-completed.md)保留了该结果。37 项测试未捕获这两种顺序错误。

2. 指南的 JSON 命令参数位置错误。`just --json doctor` 返回退出码 1，错误为 `error: --dump used with unexpected argument: doctor`。`just doctor --json` 正常输出 JSON。嵌套命令同样把 `--json` 放在 recipe 参数中，例如 `just dispatch show <id> --json`。

3. Codex 首次派发没有开始执行。`just dispatch create ... --harness codex --enqueue --json` 在 4.39 秒后返回退出码 0，合同为 `dispatched`。之后读取 pane，Codex 仍为 idle，输入框为空，报告不存在。手动用 `herdr agent prompt` 重发同一份 prompt 后，才执行 `just check`。这次复现证明初次成功返回不足以确认任务开始，尚未定位 Herdr 与适配器之间的具体根因。

4. worker prompt 缺少可定位的 coordinator 根目录。Codex 通过测试后，将相对路径报告写进目标 checkout。prompt 中的 `project-herdr receipt record` 又报 `command not found`，改用 `just receipt record` 后报 `unknown dispatch`。人工补充 `/home/cdd/project-herdr` 和 `just receipt record` 后，worker 才将报告复制回正确位置并登记 `needs_review`。clone 后无需安装 CLI 是指南前提，因此回写命令也需要在该前提下可执行。

5. Claude 尚未完成初始化，合同却已标记 dispatched。真实启动返回成功耗时 4.425 秒，但 pane 停在首次启动的 security notes 页面，未执行测试。初始化是本机前置条件，错误报告为已派发则是需要处理的就绪判断问题。

pi 的 prompt 确实送达，随后出现 `Error: 401 status code (no body)`。这是当前 provider 认证阻塞，不能判定 pi 工作流通过，也不能据此归咎于 coordinator 派发。
